# Build prompt: sidebar-git-diff

Implement `sidebar-git-diff`, a read-only, TUI-only OpenCode V2 plugin. Start with an empty repository and treat this document as the specification. The first stable version is `1.0.0`. Target OpenCode 2.3.2. Use TypeScript, Solid and OpenTUI. Read the [OpenCode TUI plugin guide](https://opencode.ai/docs/build/plugins/cli) and verify any built-in viewer behavior in the OpenCode 2.3.2 source. Do not depend on any private repository or plugin.

## Outcome

Append a **Git changes (N)** section to the session sidebar using the `sidebar.content` slot. Group uncommitted files by worktree, then by the open session tab that last recorded a successful file edit. The grouping is an estimate, not proof that a session owns all changes in a file. Omit clean worktrees. If Git status cannot be read, show an error for that worktree and keep the other results visible.

## Source of truth

1. Use the plugin’s connected OpenCode client. Resolve the active session’s directory to its project and worktree root through `client.location.get`. Read `client.vcs.status` for up to 30 worktrees: the active one, those assigned to candidate tabs, and roots from the project’s saved `client.worktree.list` inventory that contain a recorded edit. The server might run on a different machine or OS from the terminal. Use the server, not the client filesystem, for file status and attribution.
2. Use open root session tabs as the candidates, including the active session’s root tab. If tabs are off, use the current session. Read details with `client.session.get`. Only inspect sessions for the active project, including sessions launched in other worktrees or in a subdirectory.
3. Index messages in ascending order with `client.message.list`. Scan at most four pages of 50 messages per session per refresh, and at most 30 candidate sessions. Save each session’s latest edit per path and its scan position in durable TUI storage. Resume from that position on later refreshes and after a TUI restart. Re-read a page that contains an active assistant message before saving its position. Rebuild a session’s index if a committed revert removed the cursor’s message. Indicate partial history when the index has more pages to read or a read fails. Scan at most four sessions at a time.
4. Count only completed assistant file-tool calls. For `write`, use the input `path`. For `edit` and `patch`, use the `file` entries in the tool’s `metadata.files` array. Use the tool completion time, or the assistant message completion time if the tool doesn’t have one. Ignore calls without a usable time or path. Do not count failed or running tools, shell commands, inferred edits from assistant text, or inherited history from before a fork was created.
5. Normalize paths using the server’s path rules. Resolve relative tool paths against the session directory at edit time. Use the first recorded location switch to find the original directory. Track location switches in order and retain edits to earlier worktrees. Match by worktree root and root-relative path, using `/` separators. Ignore leading-tilde paths whose server home cannot be resolved. Do not use display strings as identity.
6. For each file in Git status, pick the open tab with the uniquely latest recorded edit time. Show unmatched files and ties under **Unassigned**. Preserve open-tab order for matched groups and place the unassigned group last in each worktree. Never duplicate a file across session groups in one worktree.
7. Refresh on mount and ten seconds after each scan finishes. Allow fifteen seconds for attribution and fifteen seconds for worktree reads. Cancel network reads and scheduled refresh when the section unmounts or the active directory changes. Do not add a refresh loop that overlaps a pending scan.

## Sidebar interactions

- Session headings use the session title, with the session ID as a fallback. Groups start open. Use a clickable `▼` heading when expanded and `▶` when collapsed. Show the file count on a collapsed heading. Track collapse by worktree and session in client memory so it survives polling, session switches, and returning from the diff viewer. Do not persist it to disk. The unassigned group is not collapsible.
- Show a `📁 worktree · ⑂ branch (+N)` heading for each worktree. Read the ahead count once per worktree per refresh using a read-only Git command against the checked-out branch’s locally stored remote tracking ref. Never fetch or push. Show `(-)` when there is no remote tracking ref and `(?)` when the count cannot be read. Skip local Git when the CLI uses `--server`, because the checkout may be on another machine.
- Put **Collapse all** next to **Git changes** if any listed session group is open. Show **Expand all** when all listed session groups are collapsed. Update only the listed session groups, including those below the current scroll position. Hide the action when there are no session groups. Expose the same action in the command palette without reserving a global key. Rely on OpenCode’s sidebar scrollbar when the contents overflow; do not add a nested scroll area.
- Render the status in a separate white `[A]`, `[M]`, or `[D]` badge. Keep it legible in light and dark themes. The badge is not a link. Render the filename as an underlined, wrapping link. Replace control characters for display only. Ignore right-clicks and drags.
- A filename click opens the file’s **Uncommitted** diff in a plugin route. Pass the worktree root, relative filename, and originating session ID. Read `client.vcs.diff` with `mode: "working"` in that worktree and show only the selected file. Do not call a shell or change the session location or native diff settings. `Esc` returns to the originating session.

## Package and publish

Export a default `Plugin.define` from `@opencode/plugin/tui` with ID `sidebar-git-diff` and publish it through the package’s `./tui` export. Ship TSX source; OpenCode compiles it. Use an npm lockfile, MIT license, a README with installation through `cli.json`, and scripts for type checking and checking the package tarball. Do not include a server or GUI entry point. Use GitHub Actions for package checks. A separate workflow on pushes to `main` publishes to npm’s `latest` tag via trusted publishing. Use the package version to promote `latest` from beta to stable. After that, compare commits against the source commit recorded by npm for the last release. Use the largest version bump: major for a breaking-change marker, minor for `feat:`, and patch otherwise. Do not publish again if the commit is already included in the latest release.

## Acceptance checks

- In a Git worktree with two open tabs, give each tab a different edited file and create a third file outside the OpenCode tools. The sidebar should show two session groups and one unassigned file. If the second tab later records a newer edit to the first tab’s file, the file should move to the second group on refresh.
- Collapse one group. The other group stays open and a refresh does not reopen the collapsed group. Edit a file in another saved worktree without moving the session. Confirm that its edit appears under that worktree. Use the same relative path in both worktrees to verify the edits stay separate.
- Use **Collapse all** and **Expand all** to update both groups without hiding unassigned files. When the list is taller than the sidebar, scroll down until the last file is visible. Use the command palette to toggle the groups while the sidebar heading is off-screen.
- Check the status line with an ahead branch, a branch in sync, and a branch with no remote tracking ref. Verify that it remains visible when a session group is collapsed.
- Clicking a status badge does nothing. Click the same relative filename in two worktrees and verify each link opens the corresponding **Uncommitted** patch. Press `Esc` to return to the same session with its collapse state intact.
- Install or unpack the output of `npm pack` separately from the source checkout. Load its TUI entry point in OpenCode 2.3.2 and confirm the section works. Verify that only pushes to `main` can publish, and that `fix:`, `feat:`, and breaking changes choose the expected versions.
